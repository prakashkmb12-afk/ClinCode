# ClinCode Engineering & Coding Standards

This document establishes the official coding, architectural, testing, and operational conventions for the **ClinCode** repository. All contributions must adhere strictly to these rules.

---

## 1. General Principles & Core Rules

1. **Retrieval-Only Code Rule**: Code candidate strings must **never** be dynamically generated by an LLM prompt. All suggested ICD-10 codes must originate from the Qdrant retrieval index.
2. **Assertion-Gated Processing**: Entities labeled as `absent` (negated), `possible`, `conditional`, or `family` must be excluded from standard candidate code retrieval.
3. **Evidence Pinning Invariant**: Every code suggestion output must carry verified sentence-level character span offsets into the original document.
4. **Human Finality**: Autonomous agents and GenAI modules provide suggestions and evidence; final coding authority rests exclusively with the human medical coder.

---

## 3. Pydantic & FastAPI Conventions

* **Pydantic v2 Models**: All request payloads, response schemas, and inter-service messages must inherit from `pydantic.BaseModel` with `extra = "forbid"` and explicit field descriptions.
* **Async Path Operations**: All FastAPI path operations must be declared `async def`.
* **Standard HTTP Status Codes**: Path operations must return explicit status codes (e.g., `201 Created`, `202 Accepted`, `400 Bad Request`, `401 Unauthorized`, `403 Forbidden`, `404 Not Found`, `422 Unprocessable Entity`).

## 4. Database & ORM Conventions

* **SQLAlchemy 2.0 ORM**: Use explicit `Mapped[]` and `mapped_column()` annotations.
* **Database Migrations**: Database schema modifications must be managed via Alembic migrations under `db/migrations/`. Manual SQL edits are prohibited.
* **Async Sessions**: Database access in API services must use `AsyncSession` with explicit context manager control.
* **Transaction Safety**: Code actions writing to `review_actions` and `chart_submissions` must execute within single atomic transactions.

---

## 5. Pipeline & Stage Worker Conventions

* **Idempotency & Checkpoints**: Every pipeline stage (`ocr_intake`, `deidentify`, `sectionize`, `ner`, `assertion`, `normalize`, `retrieve`, `rank`, `calibrate`, `genai`) must write a checkpoint record to `pipeline_runs` upon completion.
* **Stage Isolation**: Stages must consume typed inputs and produce typed outputs. Stage crashes must preserve previous stage outputs and quarantine poison documents without failing worker processes.
* **Provenance Tracking**: Every stage must append its model version, ONNX checksum, or prompt ID to the `provenance` dictionary attached to generated `code_suggestions`.

---

## 6. PHI Handling & Privacy Safety Rules

* **Zero PHI in Logs**: Raw clinical text, patient names, dates, MRNs, and unencrypted PHI lookup maps must **never** be output to application logs, stdout, or error stack traces.
* **Pre-Index Scrubbing**: No document text may enter Qdrant vector indexes or LLM prompts without passing through the de-identification gate (`stages/deidentify.py`).
* **Fernet Encryption**: Reversible PHI mapping dictionaries and raw text BYTEA attributes must be encrypted using Fernet keys loaded strictly from environment variables (`PHI_ENCRYPTION_KEY`).
* **PHI Canary Tests**: Test suites must include automated canary tests verifying that known synthetic PHI strings fail to appear in vector payloads or log files.

---

## 7. Testing & Quality Assurance Standards

* **Unit Testing**:
  * Character-span offset math in `sectionize.py` and `ner.py` must be covered by property-based tests (`hypothesis` framework).
  * Excludes1 conflict logic and ICD-10 hierarchy rules must be exhaustively unit-tested against test cases in `docs/coding_rules.md`.
* **Integration Testing**:
  * Asynchronous queue processing and stage checkpoint resume must be tested using `testcontainers` for PostgreSQL, Redis, and Qdrant.
* **API Contract Testing**:
  * REST API endpoints must be tested for schema compliance, RBAC matrix enforcement, and error payload formats.
* **AI Evaluation Gates (CI)**:
  * Pull requests affecting `ml/`, `services/pipeline/`, or `services/investigator/` must pass CI evaluation thresholds:
    * NER Span $F_1 \ge 0.80$.
    * Assertion Detection $F_1 \ge 0.90$.
    * Retrieval Recall@5 $\ge 85\%$.
    * Auto-accept precision $\ge 98\%$.
    * Grounding faithfulness pass-rate $\ge 95\%$.
    * Adversarial verifier kill-rate $100\%$ on planted invalid recommendations.

---

## 8. Multi-Agent Investigation Conventions

* **LangGraph Orchestration**: Agentic chart investigation workflows must be declared using typed state graphs (`ChartInvestigationState`).
* **Read-Only Tools**: Agents are restricted to calling whitelisted read-only tool functions (`note_tools`, `hierarchy_tools`, `guideline_tools`, `precedent_tools`, `rules_tools`).
* **Execution Budgets**: Investigations must enforce a hard upper bound of $\le 12$ total tool executions and $\le 2$ revision iterations.
* **Typed Findings Output**: Agents communicate exclusively by writing typed finding objects (`EvidenceFinding`, `GuidelineFinding`, `HierarchyFinding`) into shared state. Unstructured agent-to-agent conversational chatter is forbidden.

---

## 9. Configuration & Environment Management

* **No Hardcoded Secrets**: Secret keys, database credentials, API tokens, and encryption keys must be managed via `.env` files and validated using `pydantic-settings`.
* **Default Fallbacks**: Development settings must provide safe local fallbacks (e.g., `localhost` service ports), while production environments strictly require explicit environment variable overrides.

---

## 10. Git & Documentation Conventions

* **Branch Strategy**: Development occurs on feature branches (`feature/`, `fix/`, `ml/`) merged into `main` via pull requests.
* **Conventional Commits**: Commit messages must follow conventional commit syntax:
  * `feat(ner): add ONNX model export for Bio_ClinicalBERT`
  * `fix(rank): resolve Excludes1 collision logic for E11 chapter`
  * `docs(arch): update data flow sequence diagram`
  * `test(deid): add PHI canary leak assertions`
